# TAU — Паспорт похода с AI-аудитором готовности

Локальный прототип на Python 3.10+. Сервер работает на стандартной библиотеке; пакет `anthropic` нужен только для ИИ-режима.

## Запуск

```powershell
py app.py
```

Откройте http://127.0.0.1:8000. Другой порт: `py app.py --port 8080`. Остановка: Ctrl+C.

## Открыть с телефона

```powershell
py app.py --lan
```

Телефон должен быть в той же сети, что и компьютер (тот же роутер). Сервер напишет адрес вида `http://192.168.1.7:8000` — откройте его в браузере телефона. При первом запуске Windows спросит, разрешить ли Python доступ к сети: разрешите. Если сеть в Windows помечена как «Общедоступная», брандмауэр может блокировать входящие подключения; тогда переключите её на «Частную» (Параметры → Сеть и Интернет → Свойства подключения).

Пароля нет: пока сервер запущен с `--lan`, походы видит любой в этой сети. Подходит для демо, не для настоящих данных.

## Включение ИИ

```powershell
py -m pip install -r requirements.txt
$env:ANTHROPIC_API_KEY = "ваш ключ с console.anthropic.com"
py app.py
```

При запуске сервер пишет, какой режим активен. Без ключа аудит выполняет движок правил, и на экране об этом сказано. Ключ не хранится в коде и не попадает в репозиторий.

Для теста можно подключить OpenAI вместо Claude: задайте `OPENAI_API_KEY` (ключ с platform.openai.com). Если заданы оба ключа, используется Claude; явно выбрать сервис можно через `TAU_AI_PROVIDER=claude` или `openai`. Запрос, JSON-схема и проверка ответа у обоих сервисов одинаковые.

Настройки через переменные окружения: `TAU_AI_MODEL` (Claude, по умолчанию `claude-opus-5-5`), `TAU_OPENAI_MODEL` (OpenAI, по умолчанию `gpt-5-mini`), `TAU_AI_EFFORT` (`medium`), `TAU_AI_DISABLED=1` выключает ИИ.

## Как устроен аудит

1. `tau_weather.py` берёт прогноз Open-Meteo для старта и верхней точки маршрута на дату похода.
2. `tau_rules.py` считает время в пути, строит обезличенные факты и находит риски по правилам.
3. `tau_ai.py` отправляет факты в модель (Claude или OpenAI) и получает JSON по схеме: риски, чек-листы, сводку для близких.
4. Ответ проверяется: риск без ссылки на данные или с числами не из данных отбрасывается; флаги правил ИИ убрать не может.
5. Организатор принимает или отклоняет каждую рекомендацию и подтверждает паспорт. Только после этого сводку видят близкие.

Имена и телефоны в модель не передаются: участники уходят как «Участник 1, 2…».

## Карты, треки и рельеф

- **Карта** — Leaflet 1.9.4 (лежит в `static/vendor`) и подложка OpenTopoMap с горизонталями. Подложка грузится из интернета.
- **Маршруты из OpenStreetMap.** `py tools/import_osm.py` забирает размеченные пешие маршруты вокруг Алматы и пишет `catalog/osm_routes.json`. Список отношений берётся через Overpass API, геометрия — из основного API OpenStreetMap. Данные © участники OpenStreetMap, лицензия ODbL: атрибуция на карте и в каталоге обязательна, производная база распространяется на тех же условиях.
- **Рельеф** (`tau_geo.py`): высоты из Open-Meteo Elevation (Copernicus DEM, сетка около 90 м). По треку считаются длина, набор, профиль, самый крутой участок тропы и крутизна склона у тропы (доля пути по склонам 30–45° и круче 45°). Это грубая оценка, а не лавинный прогноз. Высоты кэшируются в `data/elevation_cache.json`: бесплатный Open-Meteo ограничивает число запросов и, по их условиям, предназначен для некоммерческого использования — для запуска продукта нужен платный тариф.
- **Правила по рельефу**: `AVALANCHE_TERRAIN` (склоны от 30° на треке зимой или при снеге), `CLIFFS` (склоны круче 45°), `STEEP_TRAIL` (крутой участок тропы для новичков, детей и пожилых). Цифры рельефа уходят в модель как факты, проверка ответа та же.
- **«Предложить маршрут»** (`#/propose`): GPX до 5 МБ, сохраняются только координаты и высоты, без времени записи. Защита от XML-атак, проверка, что трек в Казахстане, отсев скачков GPS.
- **Модерация** (`#/moderation`): подсказки модератору (реклама и телефоны в описании, расхождение заявленной длины, склоны круче 45°, высотный маршрут). Опубликовать или отклонить решает человек; отказ без комментария невозможен. В прототипе раздел открыт всем — в рабочей версии нужен вход для модераторов.
- **Офлайн-карт нет.** Для них нужны HTTPS-хостинг, собственный файл карты района из данных OpenStreetMap и Service Worker; надёжнее всего — мобильное приложение.

## Что работает

- Каталог: 15 маршрутов TAU с приблизительными цифрами, маршруты OpenStreetMap с треками (после импорта) и одобренные маршруты пользователей. Фильтры по активности и источнику.
- Экраны: главная, маршруты, страница маршрута с прогнозом на выбранный день, мастер похода из трёх шагов, паспорт похода, список походов. Светлая и тёмная тема, вёрстка под телефон и компьютер.
- Паспорт ведёт по шагам: группа, проверка, решения, подтверждение, ссылка близким. Блок «Что дальше» всегда показывает одно следующее действие.
- Проверка готовности с источником каждого замечания и данными, на которых оно основано.
- Вкладка «Рюкзаки»: кому что взять и почему. Кнопка «Взяли» отмечает вещь, после чего проверку нужно запустить заново; решения по сохранившимся замечаниям переносятся.
- Вкладка «Маршрут»: карта, профиль высот и рельеф (если есть трек), прогноз для старта и верхней точки, шкала светового дня с временем в пути и контрольным временем.
- Поход можно изменить: прежняя проверка помечается устаревшей.
- Сводка, расчёт трансфера и деление стоимости.
- Ссылка для близких `/p/<токен>` со сроком действия и отзывом.
- Черновик уведомления для ДЧС.

## Границы прототипа

У 15 маршрутов каталога TAU координаты и высоты приблизительные, трека нет. Треки OpenStreetMap и пользователей на местности не проверены. Офлайн-карт, GPS-навигации, оплаты, авторизации и бронирований нет. Кнопка «112» — обычная ссылка на звонок, сигнал SOS приложение не отправляет. В МЧС ничего не отправляется: сервис только собирает текст. Автоматических SMS близким нет. По умолчанию сервер слушает только 127.0.0.1; с `--lan` он доступен в домашней сети, но не из интернета. Чтобы ссылку для близких можно было открыть откуда угодно, нужен хостинг с HTTPS и авторизацией.

Известные недоработки (найдены аудитом 21.11.2026, не исправлены):
- **Походы через полночь.** Контрольное время должно быть в тот же день, что и выход. Если расчётный финиш позже полуночи, он показывается как время без пометки «на следующий день».
- **Статусы.** Поход можно перевести в любой статус в любом порядке, в том числе «на маршруте» без проверки и подтверждения.
- **Перенесённый поход.** Если поход не начали и не отменили, после контрольного времени близкие увидят «группа не отметила возвращение».
- **Проверка чисел в ответе ИИ** сравнивает число со всеми фактами без учёта единиц: «10 м/с» пройдёт, если в фактах есть любое число 10.
- Каталог и кэш высот меняются без блокировки: при одновременных запросах нескольких людей возможен редкий сбой.

## Проверка

```powershell
py -m unittest discover -s tests -v
py eval/run_eval.py
py eval/run_eval.py --ai
```

Первая команда запускает 32 теста без сети. Вторая оценивает движок правил на 28 сценариях. Третья вызывает модель (Claude или OpenAI) на каждом сценарии, тратит кредиты API и пишет метрики в `eval/results-ai.md`.

## Сценарий демо на 2 минуты

1. Главная: «Собрать поход» (5 с).
2. Мастер: пик Фурманова, завтра, выход 08:00. Опытный участник со снаряжением и новичок только с водой и обувью. «Сохранить и проверить готовность» (35 с).
3. Паспорт: итог проверки с пометкой об ИИ, замечания с именами, «На чём основано» (30 с).
4. «Рюкзаки»: нажать «Взяли» у одной вещи, «Проверить заново» — замечаний стало меньше (15 с).
5. Принять и отклонить замечания, «Подтвердить паспорт» (15 с).
6. «Создать ссылку», «Открыть, как увидят близкие» (10 с).
7. «Собрать текст уведомления» для ДЧС (10 с).

## Файлы

- `app.py` — сервер, API, SQLite.
- `tau_weather.py`, `tau_rules.py`, `tau_ai.py` — прогноз, правила, ИИ-слой.
- `tau_geo.py` — GPX, трек, профиль, крутизна; `tools/import_osm.py` — импорт маршрутов OpenStreetMap в `catalog/`.
- `static/` — страница, паспорт, экран для близких.
- `tests/` — автотесты; `eval/` — сценарии и метрики.
- `data/trips.sqlite3` — создаётся при первом запуске, не коммитить.
