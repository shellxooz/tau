# AI-карта проекта GoTAU (черновик)

По форме Приложения 2 к Положению StartUp Battle — IT FEST 2026. Места, которые команда должна заполнить сама, помечены ⟨так⟩.

| № | Вопрос | Ответ |
|---|---|---|
| 1 | Какую задачу решает ИИ | **Аудит готовности группы к конкретному походу.** ИИ сопоставляет маршрут, прогноз на высоте и снаряжение каждого участника, объясняет риски для конкретных людей, собирает личные чек-листы и сводку для близких. Он же находит опасные сочетания факторов, которые отдельные правила не ловят. Если у маршрута есть трек, ИИ получает посчитанные кодом цифры рельефа (крутизна тропы и склонов) и объясняет, что они значат для этой группы. **Без ИИ** остаются сухие флаги правил: продукт превращается в анкету с чек-боксами, пропадают персональные объяснения, сводка и перекрёстный анализ. |
| 2 | Модели и сервисы | Целевая модель — Claude Opus 5.5 (`claude-opus-5-5`) через Claude API, SDK `anthropic`. В прототипе подключён и второй сервис — OpenAI (`gpt-5-mini`, Responses API, SDK `openai`); **живые проверки на 21.11.2026 сделаны на нём**, на Claude живого прогона ещё не было. Запрос, JSON-схема ответа (structured outputs) и проверка ответа по фактам одинаковы для обоих сервисов; какая модель ответила, показано на экране аудита. Прогноз и высоты рельефа: Open-Meteo (Forecast и Elevation, модель рельефа Copernicus DEM), данные CC BY 4.0; бесплатный доступ — для некоммерческого использования, ⟨для запуска оформить платный тариф⟩. Маршруты и карта: OpenStreetMap (ODbL), подложка OpenTopoMap (CC-BY-SA). Собственных моделей нет. Использование API — по коммерческим условиям Anthropic и OpenAI. |
| 3 | Данные | Маршруты: собственный каталог. Погода: Open-Meteo. От пользователя: имена участников, опыт, возрастная группа, снаряжение, имя и телефон организатора. **В модель имена и телефоны не передаются**: участники заменяются метками «Участник N», уходят только опыт, возрастная группа и снаряжение. Медицинские данные не собираются. Треки пользователей: из GPX сохраняются только координаты и высоты, время записи отбрасывается; автор подтверждает право на публикацию. Основание обработки: согласие, которое организатор даёт при создании паспорта ⟨в MVP это текст-уведомление в форме; для запуска нужна явная отметка согласия каждого участника⟩. Данные хранятся локально в SQLite. |
| 4 | Качество | Набор из 28 сценариев (`eval/scenarios.py`). Движок правил: полнота 35 из 35 обязательных рисков, 0 ложных тревог из 51. Для ИИ считаются: доля ответов по схеме, доля флагов, которые ИИ объяснил сам, доля рисков, отброшенных проверкой (нет данных, числа не из данных), время и стоимость. ⟨Вставить цифры из `eval/results-ai.md` после прогона с ключом.⟩ В продукте измеряется доля принятых организатором рекомендаций (`/api/metrics`). Ограничение: разметку делали разработчики, ⟨нужна проверка гидом⟩. |
| 5 | Уровень риска | **Средний** (самооценка). Сбой системы может снизить качество подготовки и косвенно причинить вред, поэтому риск не минимальный. Высоким он не является: система только готовит варианты для человека (низкая автономность), не принимает решений, не управляет инфраструктурой и не подключена к службам спасения. ⟨Сверить с правилами классификации по Закону РК «Об искусственном интеллекте».⟩ |
| 6 | Ограничения и контроль | ИИ не знает состояния троп, лавинной обстановки и закрытий. Крутизна считается по модели рельефа с сеткой около 90 м и сглаживает короткие обрывы; это не лавинный прогноз, и ИИ запрещено так её трактовать. Треки OpenStreetMap и пользователей на местности не проверены; пользовательский трек попадает в каталог только после решения модератора. Прогноз — расчёт модели погоды, а не наблюдение. Оценка времени в пути приблизительная. Контроль: (а) ИИ не может убрать или смягчить флаг правил; (б) риск без ссылки на данные или с числами не из данных отбрасывается; (в) находка только ИИ не бывает «критической»; (г) организатор принимает или отклоняет каждую рекомендацию; (д) сводка видна близким только после подтверждения; (е) при сбое ИИ аудит выдаётся по правилам с пометкой. ИИ не решает, идти или нет. |
| 7 | Прозрачность | На аудите пометка: «Сгенерировано ИИ (модель) и проверено правилами GoTAU. Это подсказка, а не решение». У каждой рекомендации указан источник: правило, ИИ или оба, и раскрываются данные, на которых она основана. На странице близких указано, что сводка составлена ИИ. Если ИИ не работал, это тоже написано. |
| 8 | ИИ в работе команды | Claude Code: аудит прототипа, код сервера и интерфейса, тесты, набор сценариев, черновики документов. Gemini: первичная критика концепции и разбор критериев. ⟨Дополнить: чем делались слайды и видео.⟩ |
| 9 | Вклад команды | Концепция «Паспорта похода» и выбор сценария; каталог маршрутов и их параметры; пороги и логика правил безопасности; схема обезличивания; правила проверки ответа ИИ; разметка тестовых сценариев; ⟨интервью с гидами и туристами; дизайн; питч⟩. Архитектура «правила → ИИ → проверка → человек» — решение команды. |

Объём укладывается в 2 страницы после заполнения пометок.
